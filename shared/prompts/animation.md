# Animation request and review

Before generation, proactively ask once about style reference images when none have been supplied or adopted and availability remains unanswered, even with a written style brief. Reuse established references and prior answers; if unavailable or declined, continue with the brief and adopted project style. For newly generated animation images of any kind, use: generate a multi-frame reference sprite sheet -> directly import its frames into Pixelorama as editable frames. Preserve generated pixels and report inspection findings without automatic native adjustments. A single static image is not the multi-frame reference stage. Set only the actions, directions, timing, and frame counts the project needs; use manageable sheet batches when a large request loses consistency. Explicit native-animation repairs retain their source and authorized scope.

```text
Generate a multi-frame reference sprite sheet for [action and direction] using [approved baseline, if supplied].
Creation route and reference role: [multi-frame reference sheet for direct Pixelorama import without automatic pixel edits / explicitly requested alternative route].
Preserve [body proportions, identifying features, equipment, colors, view].
Motion intent: [anticipation, key action, contact, recovery or loop].
Anchor/contact reference: [project-specific origin or contact baseline].
Moving-part attachment: [joint or contact region, fixed part, expected overlap and contour continuity, if applicable].
Logical frame canvas and occupancy: [chosen specification].
Key poses / intended sequence: [meaningful stages].
Part ownership and occlusion: [identify near/far limbs or moving/fixed components through the sequence, where relevant].
Support or attachment phases: [what bears weight or remains connected at each meaningful stage].
Timing and loop semantics: [if established].
Delivery arrangement: [reference sprite-sheet layout and chronological frame order; labels kept outside production pixels].
Background and padding: [required alpha and complete silhouette clearance].
```

Import the actual generated frame layout into Pixelorama, then inspect all native frames and the played sequence. Check missing or duplicated parts, small features, limb/equipment continuity, material and contour consistency, contact drift, motion readability, timing, wraparound, and transitions into adjacent states. Report observed issues without proactively retouching frames. When native repair, cleanup, or authoring is explicitly requested, apply only its scoped changes in Pixelorama and inspect the affected frames, detail boundaries, and loop again before saving/exporting. A uniform frame grid or changing frame index does not establish coherent motion. Record the actual layout and findings separately from generator assumptions. Record corrections and reinspection only when they actually occurred within the requested editing scope; do not invent edits or claim import resolved a defect.

For an unfamiliar action or body plan, consult suitable motion references before choosing the poses. Start with one readable action per loop when combining actions obscures the contacts. Trace the same limb from its root through the joint to its extremity across the complete cycle, including occluded phases. A colored marker or a changed silhouette cannot replace a correctly connected limb. Locomotion needs the appropriate support and swing phases for the intended gait; do not impose a single gait or view on every subject. An explicitly requested native repair may preserve a strong generated body while redrawing defective limbs, attachments, or transitions on separate editable layers.

If text-only drafts repeat a phase or confuse part ownership, use an explicit pose or contact guide alongside the design reference. State their different roles: the reference establishes appearance; the guide establishes the sequence and part relationships. A guide is planning material, not proof that the generated result follows it. Inspect the resulting anatomy, contacts, and transitions before expanding or exporting the sequence.

Interpret contact in the adopted view. Depth can place near and far feet on different screen-space rows in an oblique or three-quarter projection. Check a consistent projected support plane or per-depth baseline rather than forcing every supporting extremity onto one universal pixel row.

For moving parts attached to a fixed object, inspect the complete joint crop in every frame at native size and integer magnification. Check the whole attachment and its material contours, including intermediate poses; a one-pixel alpha connection does not establish a sound joint. For locomotion or repeated actions, review the order of preparation, contact, displacement, and recovery, including the last-to-first transition. Distinct poses and a changing frame index establish neither causal motion nor a convincing loop. Record these visual observations separately from file, connectivity, and playback measurements.
