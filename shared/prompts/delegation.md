# Scoped delegation

Delegate for parallel ownership or genuinely independent review. Small tasks do not need a fixed team.

## Production task

```text
Task and authorized scope:
Project root and current revision:
Relevant requirements and decisions:
Read these skill/reference files as needed:
Input files and their roles:
Artwork creation route and which inputs are references versus production pixels:
Reference image or multi-frame reference sheet and actual import layout:
Style-reference availability or supplied references:
Detail findings and any explicitly requested native-edit scope:
You own these files or live document:
Required deliverable and integration point:
Relevant checks:
Other writers and out-of-scope work:
Report changes, actual validation, and remaining issues.
```

Assign one writer per shared scene or live document. Independent asset files and unrelated code can often proceed in parallel. The coordinator owns integration and resolves conflicting assumptions.

Before delegating generation, carry forward supplied or adopted style references and any previous availability answer. If neither exists, ask once whether style reference images are available, even with a written style description; do not have multiple agents repeat the question. References are optional and do not create a permission gate. New static-art handoffs follow generation -> direct Pixelorama import. Animation handoffs start with a multi-frame reference sprite sheet -> direct import as editable frames. Preserve generated pixels by default. The owner inspects and reports defects without proactively modifying pixels; file/import success is separate from visual approval. Explicit native-authoring, cleanup, and repair tasks retain their scoped editing and reinspection steps. Report actual changes and remaining issues before requested runtime integration.

## Independent forward test

```text
Use [skill path] to handle this realistic user request: [request].
Allowed workspace and side effects: [scope].
Raw project artifacts: [minimum necessary inputs].
Available capabilities: [actual environment].
Return your result and what you observed.
```

Do not include the intended verdict, suspected bug, or preferred fix unless necessary for the task. Keep generated test artifacts isolated. Review the outcome and change instructions only for observed failures, rather than accumulating rules for hypothetical cases.
